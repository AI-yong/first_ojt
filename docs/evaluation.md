# 평가 요약

## 검색 평가

검색 평가의 대상은 답변 생성이 아니라 상품 retrieval 단계입니다.

- 상품: 2,419개
- 구조화 조건: SQLite SQL 필터
- 의미 검색: `jhgan/ko-sroberta-multitask`, 768차원
- 최종 후보: Dense 점수 기준 최대 50개
- 최종 정렬: 명시적인 가격·평점·리뷰 정렬 또는 Cross-Encoder
- 평가 분할: dev 16개, 고정 test 16개

| 방식 | nDCG@10 | MRR@10 | Precision | Recall | F1 | 평균 결과 수 |
|---|---:|---:|---:|---:|---:|---:|
| Dense top-50 | 0.880 | 0.844 | 0.894 | 0.621 | 0.733 | 50.0 |

현재 결과에서는 별도의 어휘 검색을 결합해도 Dense top-50보다 개선되지 않아 공개 버전에서는 채택하지 않았습니다.

## 계획 모드 평가

계획 모드는 긴 요청을 무조건 더 잘 처리하기 위한 기능이 아니었습니다.

- 승인과 조회가 여러 갈래로 얽혀 모델이 후속 작업을 놓치는 요청에서는 도움이 됐습니다.
- 서로 독립적인 작업을 한 단계씩 왕복하면 전체 대화가 반복 입력되어 토큰 비용이 증가했습니다.
- 예산 초과 방지, 재고가 없는 상품의 대안 선택 같은 문제는 계획보다 애플리케이션 정책과 검증 규칙으로 처리해야 했습니다.
- 따라서 공개 버전에서는 계획 모드를 기본적으로 끄고 선택 기능으로 제공합니다.

## 평가의 한계

1. 검색 정답은 상품 데이터와 사람이 작성한 패러프레이즈로 만든 silver label입니다.
2. 운영 사용자의 실제 질의 분포를 대표하지 않습니다.
3. 단일 로컬 환경의 지연시간은 동시 요청과 대규모 인덱스 비용을 포함하지 않습니다.
4. 계획 모드 평가는 모델의 비결정성과 채점 규칙에 영향을 받습니다.
5. 최종 서비스 판단에는 사람의 등급형 관련도 평가와 클릭·장바구니·구매 로그가 필요합니다.
